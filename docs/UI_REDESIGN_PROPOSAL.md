## 第一部分：Editor（:8868）三屏重构

### 现状问题（事实，2026-07-23 截图复核）

- Hub 中心约 70% 空白，主操作只有一个"AI 创建故事"裸按钮，无生产感。
- 项目列表全是"未命名互动故事"+时间戳，看不出哪个能玩、哪个卡在哪个阶段。
- "分镜→蓝图→合成"缩在角落一行小字，核心价值链隐形。
- 右栏是开发者日志流（provider 配置重复刷屏），不是创作者视图。
- ComposeStudio.tsx 已 9357 行——没有正确归属生产行为的地方，功能只能往最后一个页面堆。

### 总体设计：三屏一轨

**一轨**：阶段轨道（脚本→蓝图→合成→导出）为全局复用的同一视觉语言——项目卡的迷你轨、工作台的主轨、新建流程的进度环，用户学会一次处处认得。

**屏 1 项目库（卡片画廊，已确认 2026-07-23）**：
- 项目卡片墙按最近打开排序；每卡含四格迷你轨道（实心=该阶段完成）、当前阶段文字、可玩徽标（dist 存在才显示）、更新时间。
- 主操作区仅两个动作：`▶ 继续上次`（localStorage 记忆最近项目+阶段）与 `＋ 新建互动故事`。
- 右栏（可折叠）：环境状态人话版（文本模型/图像服务就绪态，未就绪给"去设置"）、最近动态（来自项目更新时间排序）、诊断日志默认折叠收纳。

**屏 2 流水线工作台（项目内，方向已于 2026-07-22 确认）**：
- 顶部阶段轨道带健康徽章（卡数/编译错误/校验/可玩性），四区契约保留（左结构/中画布/右属性/顶全局）。
- AI 协作环嵌入各阶段：生成候选→规范化→编译→校验→修复五态就地显示，evaluator 失败红标 + 一键修复（`ai/fix/scripts`）。
- 合成阶段中央直接嵌可玩运行时预览。

**屏 3 新建流程（单屏，已确认 2026-07-23）**：
- 单屏表单：一句话创意 + 分支选择点数/每点选项数/结局数 →「开始生成」。
- 生成中同屏显示实时五态环（生成候选→规范化→编译验证→结构校验→完成/失败），失败红标+人话原因+一键修复。
- 完成后落在工作台蓝图阶段（用户从结构开始审），不丢回项目库。

### 阶段轨道"完成"判据（已认可 2026-07-22）

| 阶段 | 徽章内容 | 完成判据 |
|---|---|---|
| 脚本 | 卡片数、结构校验 | `analyze/scripts` 无 errors |
| 蓝图 | 节点数、编译 errors、结局可达 | `validate/blueprint` 无 errors 且 ≥1 可达结局 |
| 合成 | 节点数、校验警告 | `validate` 通过 |
| 导出 | dist 存在性 | dist/index.html 磁盘事实 |

### 明确不动的部分

- 四区契约、右侧唯一编辑入口、深色基底 + `#5eccff`、三态组件、无研发术语、未配置 Provider 动作置灰+原因。
- 后端 API 全部复用（纯前端重构）；ComposeStudio 拆分是 E4 工程动作，不改变功能语义。

### 实施分期

| 期 | 内容 | 验证 |
|---|---|---|
| E1 | 项目库（卡片墙+迷你轨道+右栏状态化+继续上次） | typecheck；卡片阶段与磁盘事实一致 |
| E2 | 新建流程（单屏+五态进度环） | 生成链路真实进度可见，失败可修复 |
| E3 | 工作台阶段轨道+健康徽章 | 三层判据与后端校验一致 |
| E4 | AI 协作环 + ComposeStudio 拆分 | typecheck + 编辑器契约复核 |

## 第二部分：Control-console（:8870）聊天式治理工作台

### 现状问题（事实）

- 现状 = 聊天框 + 诊断面板（`ControlConsoleMainPanels.vue` 1070 行）。后端能力（session 步骤图、逐步 evaluator、证据快照、事件流、模型台账、质量门、生命周期状态机）几乎全部未呈现。
- 后果：运行机制不可见（黑盒）、审核积压（实测 56 个 session 永远停在 `waiting_review`）、已实现的治理能力无处展示。

### 定位（已确认）

**Console 是聊天式产品治理端；生产入口归 TalkScene 编辑器页面。**
聊天保持为交互主轴，不改为工单式工作台；但聊天背后的一切必须透明——可交互、可操作、可监察，生产过程不黑盒。

### 设计：聊天主轴 + 三处透明化增强

```
┌ 顶部态势带（常显，可折叠）──────────────────────────────────────┐
│ 服务：OMLX● Server● Editor● Hermes●  三道闸：配置✓→预检✓→模型✓   │
│ 生命周期：[启动][暂停][恢复][停止]（保护动作，二次确认）            │
│ 路由：default omlx/Qwen3.5-9B · review hermes/gpt-oss-20b       │
├ 聊天主区（治理对话流）──────────────────┬ 监察右栏（dock 可开合）─┤
│ 用户：一口气生产一个灯塔故事…            │ 实时事件流               │
│ ┌ 🤖 任务卡片（内嵌对话，非跳转）──────┐ │ 模型调用台账             │
│ │ ●创建 ✓ ●配置 ✓ ●脚本 ✓11卡        │ │ phase/provider/tokens/耗时│
│ │ ●Bible ✓ ●编译 ✓ ●评审 ◌待审核     │ │ ──────────────         │
│ │ ●修复 ⊘跳过 ●合成→导出 ⊘阻断▾原因  │ │ 质量门：86 ✓  fallback:无│
│ │ [展开证据快照] [查看 evaluator]     │ │ ──────────────         │
│ └───────────────────────────────┘ │ │ 审核队列 (3) [全部展开]   │
│ ┌ ◌ 审核卡片 ─────────────────────┐ │ │ · 评审蓝图 2分钟前        │
│ │ "智能体评审交互蓝图" 请求执行      │ │ │ · 写入脚本 1小时前        │
│ │ 依据：确定性评审 92 分 / 证据▾    │ │ │                        │
│ │ [✓ approve]      [✗ reject]    │ │ │                        │
│ └─────────────────────────────────┘ │                        │
│ 🤖 最终回答（基于 artifacts，可溯源▾） │                        │
└────────────────────────────────────┴──────────────────────────┘
```

### 三条硬原则

- **任务在对话流内可视化**：聊天触发的每个 session 渲染为内嵌任务卡片（步骤图：逐步状态/evaluator/证据快照/阻断原因），实时更新，不跳页。生产过程全程透明，但入口与交互仍是聊天。
- **审核全部记录、全部可查**：审核点以对话内卡片呈现（摘要+证据+approve/reject）；每个审核决定（含历史）进入独立"审核记录"视图，可按 session/时间/决定检索——56 个积压一览无余；批量 approve 仅限低风险步骤类型，且每条仍单独落 review record（治理要求：审核记录完整，不得因批量而省略）。
- **已实现能力全部有展示位**：态势带（服务状态机/三道闸/生命周期/路由）、监察右栏（事件流/模型台账/质量门/fallback 红标）、监督会话与 skill proposals 归入"治理"标签页——不新增黑盒，也不藏已有能力。

### 信息架构调整

- 聊天页保持默认页，"任务卡片"是其消息类型之一（reasoning 自由问答语义不变）。
- 新增"审核记录"与"治理"两个标签页；诊断面板内容并入态势带与监察右栏。

## 第三部分：实施分期（确认设计后细化）

| 期 | 内容 | 验证 |

| P1 | Console 对话内任务卡片（步骤图运行器内嵌聊天流）+ 审核卡片就地化（纯展示层，后端 API 全部现成） | e2e 脚本重跑，UI 逐步状态与 session artifacts 一致 |
