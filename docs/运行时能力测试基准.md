# 运行时能力测试基准（32G / 8K·16K 硬约束）

> 生效：2026-08-24，用户明确指令。
> 本文件是守护台（Hermes + OMLX）能力设计与测试的**硬基准**：所有测试设计、通过标准、配置默认值以其为准。
> 修改本基准必须经用户明确指令，并同步登记 `ai/memory/DECISIONS.md`。

## 1. 硬件与资源硬约束（写死）

- 机器总内存 **32GB**；模型（权重 + KV cache）可用上限 **23–25GB**。
- **测试期上下文预算 8192 tokens（8K）**，任何链路、任何测试不得超出；**16384（16K）为机器绝对硬顶**，仅后续阶段经用户确认后上调。
- OMLX 侧模型加载上下文必须设为 8192，KV cache 计入 23–25GB 预算。
- 出图（ComfyUI）与模型推理内存互斥，沿用 AUTO-R01 资源调度，禁止并行抢内存。
- **实测内存事实（2026-08-24，Qwen3.6-27B-MLX-4bit / 4bit）**：权重常驻 17.44GB；KV+SDPA 含 ~5.5GB 固定预留（随实际 token 数仅微增），prefill 合计 ~23.1GB。macOS Metal cap 当前 22.99GB（`iogpu.wired_limit_mb` 24,960MB 派生）——**低于** 23–25GB 预算，必须提限（`sudo sysctl iogpu.wired_limit_mb=26624`）或 OMLX 侧 KV 量化/降载，否则任何 prompt 都被 prefill guard 拒绝（HTTP 400）。

## 2. 运行时记忆 = 超短（写死）

上下文是稀缺资源，运行时只保留超短记忆，对应 control 配置：

| 项 | 基准值 | 配置位置 |
| --- | --- | --- |
| 上下文预算硬顶（测试期） | 8192 tokens | `shortTerm.maxContextTokens`（binding 钳制元数据） |
| 输出预算 | ≤ 2048 tokens | `shortTerm.maxOutputTokens` |
| 聊天历史回放 | ≤ 6 条（3 对问答） | `workflow.replayWindowMessages` |
| 推理链回放 | ≤ 4 条 | `workflow.reasoningReplayWindowMessages` |
| 上下文压缩阈值 | 75%（≈6144 tokens），超限走滚动压缩摘要 | `compressChatMessages`（2026-08-24 起为滚动压缩，不再直接丢弃） |
| 记忆文件注入（control 侧） | 每文件 ≤1500 字符 / 总量 ≤4500 字符 | `DEFAULT_MEMORY_OVERLAY_*`（8K 配额） |
| 记忆文件注入（gateway 侧） | 每文件 ≤800 字符 | hermes `config.yaml` `context_file_max_chars` |
| 咨询流外部记忆注入 | ≤4 对 × 140 字（≈1200 字符） | `agentStreamRoutes.buildAgentStreamExternalMemoryBlock` |

## 3. 长记忆全部外部化（写死）

模型上下文内**不允许**依赖长记忆。长记忆唯一归宿是外部存储/检索：

| 外部记忆 | 位置 / 入口 |
| --- | --- |
| 每日聊天落盘 | `ai/chat/YYYY-MM-DD.json` |
| 记忆文件 | `ai/memory/STATUS.md` / `TASK_QUEUE.md` / `DECISIONS.md` / `LONG_TASKS.md`、`ai/MEMORY.md` |
| Hermes 历史会话检索（FTS5） | `GET /api/control/hermes/session-search?q=` |
| 治理证据（reasoning sessions / 事件 / 审核） | `state/` |
| 项目产物真相源 | `storage/projects/` |

问答或任务需要历史事实时，必须先检索外部存储再作答，不得依赖上下文驻留。

## 4. 稳定性优先（写死）

- **慢可以**：单次请求超时维持 500s（`HERMES_CHAT_REQUEST_TIMEOUT_MS`）；长任务必须走 `/ai/tasks` 暴露进度。
- **断/崩不行**：
  - 任何失败必须显式收敛为 `failed` / `blocked` 并携带错误消息；
  - 禁止静默吞错（含空回答被标记为"完成"）；
  - 禁止确定性兜底冒充成功（生产纪律既有条款，延续有效）。
- 有内存超限风险的操作（超预算上下文、推理与出图并发）必须**前置阻断**，不允许跑到崩溃。

## 5. 测试基准（分组通过标准）

### A 组 · 链路冒烟（前置必过）
- `今天的日期是什么？` → 分流 `answer_only`（R011），`final.answer` 非空。
- `用一句话说明 apps/editor 目录是干什么的？` → 纯问答，不触发工具与生产副作用。
- 通过标准：回答非空、session 终态 `completed` 且回答真实来自模型。

### B 组 · 跨轮记忆（检验外部记忆检索，不是检验上下文驻留）
- `我们约定一个暗号：蓝鲸742。请问暗号是什么？` → 隔若干轮 → `我刚才说的暗号是什么？`
- `storage/projects 下有哪些项目？` → `第一个项目是什么时候创建的？`（指代解析）
- 通过标准（8K 基准下）：**答案来自外部记忆机制**（聊天落盘有界注入 / session-search / 回放窗口内）即算通过；超出机制覆盖的遗忘，记为能力差距而非测试失败。
- 现状（2026-08-24）：agent-stream 咨询路径已接入外部记忆有界注入（最近 ≤4 对 × 140 字，来自聊天落盘），B 组暗号类（近窗口内）应可通过；跨长距离召回依赖 session-search 工具（gateway 侧已保留该 toolset）。

### C 组 · 长线压力（12+ 轮）
- 围绕一个故事创意连续 12 轮推进（题材→主角→冲突→章节→反转→标题），末轮要求汇总大纲。
- 通过标准：**全程不崩、不空答、失败显式**；汇总质量允许受外部检索能力限制，但每轮请求上下文不得超过 8192 tokens（压缩日志可见 `originalCount → compressedCount` 与滚动压缩摘要行）。
- 中途插 3 轮无关话题再回主线，验证相关度召回与外部检索，不允许出现 5xx / 进程退出。

### D 组 · 分流正确性
- 祈使句 `创建一个悬疑故事项目` → 回退确定性链并触生产门禁。
- 问句 `可以用 talkscene 创建悬疑故事吗？` → `answer_only`，零生产副作用。

### E 组 · 证据链
- 每轮后查 `GET /api/control/agents/hermes-manager/chat-history`（落盘完整）与 reasoning session 事件流。
- 通过标准：空回答 / gateway 错误必须呈现为失败态并带消息，禁止显示为成功。

| 差距 | 位置 | 状态 |
