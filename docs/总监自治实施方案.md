## 0. 总设计原则

1. **总监 = 规则化编排器 + 失败处置策略表 + 项目级生产约定，不是大模型**（治理第 8 节）。
2. **看门狗只恢复操作类失败**（瞬断/卡死/门禁等待/格式坏/资源争抢），**内容类失败只能限次重试，超限停摆等人工**——失败即停高于一切自动处置。
3. **守护台零项目专属代码**（终态）：工作流声明（步骤图/动作→端点/门禁/策略表/公式）由项目侧发布描述文件，守护台读声明执行；任何项目接入即获得同等自治能力。
4. **一切自动处置留证据**：reasoning 事件流 + 治理审计 + `/ai/tasks` 台账 + 项目落盘真相源，四者一致才算发生。

## 3. 两仓分工（建设归属）

### 3.1 gamestudio 仓（项目侧）

- 实现《可指挥生产项目契约 v1》全部义务端点（注册表/能力清单/审核三端点/任务台账/证据规则）——**已基本齐备**，缺 workflow.v1 描述文件发布端点（V2.0）。
- 内容侧智能全部留在本仓：提示词/schema/质量评审/出图链路/审核门禁规则。守护台不碰内容语义。
- 本仓缺陷与未实现项统一记 `docs/PRODUCTION_DEFECTS.md`，随版本核销。

### 3.2 local-agent-control 仓（守护台侧）

- 看门狗（sessionGuardian）与托管模式：瞬断续跑/orphan 恢复/托管批准/失败停摆/门禁过闸——已实现，V1.x 补资源自愈与策略表数据化。
- 项目注册表 directorProfile：承载各项目总监档案（策略表/公式/阈值）——V1.2。
- 工作流声明执行器：读 workflow.v1 描述文件驱动步骤——V2.0，替代 storyProductionWorkflows 的代码模板。
- 守护台契约文档：`docs/项目总监与看门狗契约 v1.md`。

## 4. 验证纪律（每个版本必须执行）

1. 每版本验证门 Must Pass 项全过才允许宣称达成；验证证据落 `docs/` 对应批次记录（参照 PRODUCTION_DEFECTS.md 批次格式）。
2. 任何"已实现未验证"项不得写进"已验证"区；验证通过=真实故事/真实链路实证，单测只算半证。
3. 审批默认全开（2026-10-14 用户指令）：新会话默认托管，全类型审核 Guardian 自动批准并留审计；显式 managed:false 可关闭。失败即停语义保留：策略表外失败停摆等人工。
4. 版本回退：某版本验证门不过，回到上一稳定版本标记，缺陷记档后修复重验。
