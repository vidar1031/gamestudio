# 可指挥生产项目契约 v1（项目侧）

> 版本：v1.0（2026-10-13 定稿）
> 适用：任何要被守护台"项目总监（看门狗）"指挥完成生产链的项目（gamestudio、forge-studio 等）。
> 本契约规定**项目侧必须实现什么**才能获得被指挥资格；守护台如何消费见 local-agent-control
> `docs/项目总监与看门狗契约 v1.md`。接入基础规则以 local-agent-control `docs/接入协议.md` 为准。

---

## 1. 总原则

1. 项目拥有**内容与真相**：提示词、schema、质量评审、生产执行、落盘真相源全部在项目侧；守护台只做编排、门禁、资源、看门狗。
2. 项目的生产行为必须**可声明、可观测、可门禁、可断点**——缺任何一项即失去被指挥资格。
3. 本契约与 `docs/PROJECT_GOVERNANCE.md` 第 8 节冲突时，以治理文档为准。

## 2. 必须实现的端点与文件

| 义务 | 端点/文件 | 语义 |
| --- | --- | --- |
| 事件注册表 | `GET /api/events/registry`（免登录只读） | registry v1：全部可派发事件及 payloadSchema/reviewRequired/transport |
| 能力清单 | `<repo>/apps/server/events/project-manifest.v1.json` | 能力 id/类型/审核策略/资源类别/事件映射（接入协议 §5） |
| 生命周期事件 | `<provider>.lifecycle.status/start/stop` | 绑定门禁强制族（接入协议 §5.1） |
| 健康探测 | `/api/health` | 守护台活性探测 |
| 审核队列 | `GET /api/projects/:id/ai/reviews?status=pending` | 待决审核列表（含 reviewId/phase/prompt/execute） |
| 审核决断 | `POST .../ai/reviews/:reviewId/approve`、`POST .../ai/reviews/approve-all` | 守护台托管过闸调用点；lock_confirm 阶段不放行自动批准 |
| 长任务台账 | `GET /api/projects/:id/ai/tasks` | 长任务（渲染/锁定/批量）进度真相，守护台轮询与超时复核依据 |
| 项目真相源 | `storage/projects/<id>/` | 一切产物以磁盘为准；守护台证据链据此核对 |
| 工作流描述文件（V2.0） | `GET /api/workflow/registry` 或 `<repo>/workflow.v1.json` | 生产链声明：步骤图/动作→端点映射/审核门禁/失败策略表/结构公式 |

## 3. 生产链行为规范

1. **步骤幂等**：同一步骤重复执行不得产生重复产物（创建按名复用、写回覆盖、已锁定不重抽）。
2. **门禁显式化**：凡需要人/AI 审核的环节必须落成审核记录（pending→approved/rejected），禁止隐式跳过；审核未决时生产链必须停在该环节并返回明确的 waiting 阶段标识（`waiting_<phase>_review`）。
3. **失败分类**：返回错误必须可归类——瞬断（retryable）、门禁等待（waiting_*_review）、内容不过（score/review_not_passed）、资源（oom/prefill_guard/provider_down）、业务死锁。守护台策略表按类处置。
4. **进度可见**：>30s 的操作必须进 `/ai/tasks` 台账（kind/stage/message/progress），禁止黑盒同步长跑。
5. **出图即压**：生成图按用途分层压缩（立绘无损 WebP、背景 JPEG q90、候选 WebP q92），禁止落未压缩大 PNG。
6. **证据链完整**：生成物必须带可追溯元数据（prompt/seed/model/reviewId），评审结论留档 `reviews/image_reviews.jsonl`。

## 4. 被指挥时的行为约定

1. 守护台托管会话发出的事件派发视为操作员授权行为；项目侧审核三阶段（pre_generate/lock_confirm/scene_bind）对托管会话均可自动过闸（2026-10-14 用户指令修订，全部留审计）；非托管会话仍全人工。
2. 项目侧不得拒绝携带合法租约/凭证的调用；资源互斥由守护台调度器裁决，项目侧只如实上报占用。
3. 项目侧发现数据损坏/真相不一致时，必须以明确错误码返回（不得静默兜底造假）。
