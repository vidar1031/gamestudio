# 工程升级实施方案

> 版本：v0.9 提案（2026-10-19 起草，待批准后转 v1.0 实施态）
> 说明：本文是工程线专项方案（曾用内部代号"换羽"），属具体任务文档；全局统筹层文档（产品说明书/需求规格等）不引用本代号。
> 适用：talkscene 仓 + local-agent-control 仓的工程重构、整体优化与升级。
> 命名取意：换羽——鸟不换骨、不换飞行能力，只逐根更换羽毛。本计划同理：**内核（生产链/治理/调度）不动，外壳（交互/代码组织/品牌）逐片更换**。
> 关联文档：`docs/总监自治实施方案.md`（V 版本路线，本计划不替代它，是它的工程外壳姊妹篇）、`docs/UI_REDESIGN_PROPOSAL.md`（E3/E4 未实施项由本计划 P1 承接）、`docs/PRODUCTION_DEFECTS.md`（缺陷登记处）、`docs/PROJECT_GOVERNANCE.md`（治理基线）。

---

## 1. 诊断（证据先行，不接受印象判断)

| 症状 | 证据 |
|---|---|
| 内核超前于外壳 | 治理链（三级审核/托管审批/资源互斥/失败策略表）已市场稀有；交互层弹窗套弹窗、双界面跳跃，孔融让梨全天生产由会话+台账驱动，编辑器弹窗链零使用 |
| 单文件巨兽 | `apps/server/src/index.js` 13.6k 行、`controlServerCore.js` 15.4k 行、`ComposeStudio.tsx` ~9.5k 行——模块边界靠注释分区，新人/新 agent 上手成本高 |
| UI 流程硬编码后端状态机 | 锁定事物七步向导的步骤顺序是 UI 写死的，与服务端出图总账（coverage）重复表达同一事实，已发生多次两侧不一致事故 |
| 债务已自愈一半 | 缺陷登记/ADR/版本火车/双跑对照已在自发使用（`PRODUCTION_DEFECTS.md`/`DECISIONS.md`/V 路线），缺显式方法论声明与统一验收口径 |

**结论**：不需要重写，需要"活着换壳"。方法论选型：**绞杀者模式（新壳并行生长）+ 适应度函数（每改动跑基线）+ Tidy First（整理与功能改动不混提）+ 契约版本不动（改名/重构不碰真相源）**。

## 2. 总原则（底线，不可绕过）

1. 真相源不动：`storage/projects/**`、`packages/schema` 的 V1 契约字段、API 路径语义，全程不改名不迁移。
2. 生产链保护行为不动：生命周期控制、三级图片审核、失败即停、托管审批语义。
3. 每阶段有适应度函数（验证门），不过门不进入下一阶段；每波迭代结束必须有一个可演示增量。
4. 整理与功能改动不混提交（Tidy First）；重构波次内禁止夹带新功能。
5. 改名是表现层操作，与重构分开成独立小波，不纠缠。

## 3. 阶段路线（P0→P4）

| 阶段 | 名称 | 目标 | 验证门（Must Pass） | 估计波次 |
|---|---|---|---|---|
| P0 | 基线与改名（热身） | 适应度函数全部可一键复跑；品牌名更换落地 | §4 全部基线脚本入库并跑通；改名后四服务健康+测试全绿 | 1 波 |
| P1 | 编辑器外壳换羽 | 项目工作台单页化；锁定向导解体为资产卡片状态机；审核内联；ComposeStudio 拆分（承接 UI_REDESIGN E3/E4） | 孔融让梨只读回归零差异；新壳完成 1 个真实场景编辑任务；Golden Master 截图对照无回归 | 3–4 波 |
| P2 | 服务端分层拆分 | `index.js` 按域拆为路由模块（story 族/review 族/studio 族/生命周期族），13.6k → 主文件 <2k | `node --check` 全过 + 冒烟 + 四阶段生产基准不回归 | 2–3 波 |
| P3 | 控制面瘦身与声明衔接 | `controlServerCore.js` 的 step executor 族拆出到 `workflows/executors/`；与 V2.0 workflow.v1 声明化对齐接口 | 守护台测试 17+ 套件全绿；声明/代码双跑对照一致 | 2 波 |
| P4 | 双界面边界终局 | 评审"守护台吞并生产交互 vs 编辑器聚合"方向并定型；对接 conformance | 方向决策 ADR 落 `DECISIONS.md`；选定方向的代表性任务全链通过 | 1 波（决策+试点） |

### P0 详节（从哪里开始——就从这里）

- 动作 1：**黄金基线入库**。孔融让梨当前态固化为基线：走查截图集、plan.json/story.json 关键指纹、四阶段生产基准结果。落 `testcases/talkscene/baseline/`。
- 动作 2：**适应度函数脚本化**。一条命令跑全部护栏（见 §4），挂 `npm run fitness`。
- 动作 3：**改名波**（独立提交）：包名/UI 标题/文档/脚本注释；不动 API 路径、不动存储目录、不动 schema。候选名见 §6。

### P1 详节（编辑器外壳，绞杀者执行）

- 新壳并行生长：新增 `apps/editor/src/workbench/`（项目工作台单页），旧四工作室+弹窗保留；顶栏加"新版工作台"开关（特性开关，默认关）。
- 解体顺序（每波一个可演示增量）：
  1. 波 1：工作台骨架——左栏故事结构树（场景/资产合一）+ 中栏画布 + 右栏属性/审核二合一；只读浏览先通。
  2. 波 2：资产卡片状态机——候选→评审→锁定→线稿→变体全部落在卡片上（锁定事物向导的七步页退化为只读总览）。
  3. 波 3：任务时间线内嵌中栏（`/ai/tasks` 台账实时流，消灭黑盒弹窗）；审核卡片内联右栏。
  4. 波 4：ComposeStudio 拆分为画布层/编排层/属性层三模块（承接 E4）；旧壳进入冻结公告。
- 每波退出：旧壳同任务双跑对照 + 截图基线比对 + typecheck 绿。

### P2 详节（服务端分层）

- 只搬不拆义：按既有注释分区整体迁移为 `apps/server/src/routes/*.js` 注册模块，函数级零改动；`index.js` 只留装配。
- 顺序：story 状态/摆位族 → review 族 → 锁定/线稿族 → studio/生命周期族。每族一波，每波跑全量护栏。
- 明确不做：本阶段不改任何行为语义、不动函数签名（那是 P3+/各专项的事）。

### P3 详节（控制面）

- executor 族按 action 域拆出纯函数模块；`controlServerCore.js` 留编排骨架。
- 顺势对齐 workflow.v1 声明化接口（为总监自治 V2.0 铺路，但不提前实现 V2.0）。

### P4 详节（边界终局）

- 以 P1–P3 后的真实使用数据评审方向 A（编辑器聚合）vs 方向 B（守护台吞并），出 ADR，试点一个任务定型。

## 4. 验证体系（适应度函数，一条命令全跑）

| 层 | 护栏 | 命令/出处 |
|---|---|---|
| 静态 | 类型检查 + 语法检查 | `npm run typecheck` + `node --check` 各入口 |
| 单元 | control 17 测试套件 | `node --test scripts/test/*.test.mjs`（local-agent-control） |
| 生产基准 | 四阶段联调基准 | `bash scripts/test/smoke_test_pipeline.sh` |
| 黄金基线 | 截图/指纹对照 | `testcases/talkscene/baseline/`（P0 新建，Playwright 探针同口径） |

通过口径：**四者全绿才算一波完成**；任一红即回本波修复，不带病前进（与生产链"失败即停"同语义）。

## 5. 快速迭代机制

- 波次节奏：每波 ≤5 个工作日，结束必须有可演示增量 + 护栏全绿 + `PRODUCTION_DEFECTS.md`/能力矩阵同步更新。
- 绞杀切换：新旧外壳并存期内全部改动双壳验证；旧壳模块冻结公告后只收缺陷修复。
- 回退：特性开关 + 每波独立提交；任何一波验证门不过，整波回退不留半截。
- 评审节奏：每波结束在守护台留 reasoning 证据链（计划/执行/验收记录），人审一次放行进下一波。

## 6. 改名机制（P0 内执行）

- 范围白名单（可改）：npm 包名 `@talkscene/*`、UI 标题/文案、README/docs 标题、脚本注释、仓目录名（可选）。
- 黑名单（不动）：API 路径、`storage/` 目录、schema 字段、端口、事件名、git 历史。
- 候选名（待定，你拍板）：**织话机 StoryWeaver**（推荐：叙事+分层合成双关，不撞 forge-studio）/ 绘本工坊 Pictale Works / 话本机 StoryPress。
- 改名后旧名在文档归档区保留别名注记一次，之后全仓一致。

## 7. 风险登记

| 风险 | 缓解 |
|---|---|
| 并存期双壳维护成本 | 并存期硬上限：P1 不超过 4 波，到期旧壳冻结 |
| 拆分引入隐藏回归 | 适应度函数不过不放行；黄金基线逐波对照 |
| 改名波及外部接入方 | 黑名单不动 API/存储；control 仓接入配置无需变更 |
| 资源环境（32G 内存墙）拖慢验证 | 护栏脚本支持离线段（无出图段先跑），出图段走既有恢复模式 |

## 8. 与既有方案的关系

- 本计划管"工程外壳与代码组织"；《总监自治实施方案》管"生产自治能力"。两条线验证门互不替代：本计划 P 门过 ≠ V 版本门过。
- P1 承接 `UI_REDESIGN_PROPOSAL.md` 未实施项（E3 阶段轨道主轨、E4 ComposeStudio 拆分），原提案其余已落地项不动。
- P3 为 V2.0 声明化前置工程；P4 结论喂给 V3.0 conformance。
