# 狼来了内容质量闭环工作流（从守护台聊天发起）

> 用途：从守护台聊天处发起《狼来了》互动故事生产，并跑通「生成 → 完整度核实 → 定向修复 → 再核实」的内容质量闭环，直到判定通过。
> 全程可观测、可审计；任何失败显式呈现，不放行假成功。

## 一、前置条件（先确认再开始）

| 检查项 | 确认方式 |
| --- | --- |
| Control Server / 守护台在线 | 守护台左下角「Control 在线」 |
| Hermes 运行中 | 左下角「Hermes 运行中」（未运行点右上「一键启动 Hermes」） |
| OMLX 在线且模型已加载 | 左下角「OMLX 在线 · N 模型」；配置模型 Qwen3.6-27B-MLX-4bit 已加载（设置页可探测） |
| ComfyUI 在线 | 治理页「运行健康」卡片或 `curl http://127.0.0.1:8188/system_stats`；未启动则手动 `cd /Volumes/ovokit2t/ComfyUI && sh ./start.sh` |
| 审核模型可用 | 设置页「审核模型」= moonshot / kimi-for-coding（Kimi key 已配置） |

## 二、聊天发起生产（一步）

守护台 → 聊天页，输入并发送（建议勾「自动直跑模式」免逐步确认）：

```
创建一个狼来了互动故事，采用背景+立绘分层合成方式出图：一口气完成 P0 文本 + P1 图片资产的全链路交付——脚本、出图、校验、导出可玩 H5。
```

预期：任务执行链出现 22 步（创建→配置→脚本→写回→Story Bible→蓝图编译→蓝图评审→修复→图片预检→合成→校验→导出→资产计划→透明立绘绘制锁定→背景批量渲染→placements 立绘站位→校验→重新导出→记忆同步×3→最终回答）。

## 三、过程中的观察点（不需要干预，只需看）

- **聊天页**：任务执行链逐步点亮、执行日志滚动事件
- **治理页**：「资源互斥」卡片可见出图前模型自动卸载、出图后自动回载的交换记录；「操作审计」有每个动作留痕
- **写入审核点**（写 STATUS/TASK_QUEUE 等）：全审模式下需批准；直跑模式自动通过
- 预计耗时：60-100 分钟（出图占大头）

## 四、产出验收（终态 completed 后）

1. 聊天页最终回答会给出：项目 id、导出地址、每步 PASS/FAIL、评审分数
2. 打开可玩地址实际玩一遍：`http://127.0.0.1:1999/demos/<项目id>/latest/dist/index.html`
3. 编辑器打开该项目可查看/调整：节点、角色立绘（透明底）、背景、placements 站位

## 五、内容质量闭环（本工作流的核心）

```
完整度核实 → 若有失败节点 → 定向修复 → 重新核实 → …… 直到通过
```

1. **核实**：聊天输入 `gamestudio 完整度核实 <项目id>`（或编辑器合成工作室顶栏「完整度核实」按钮）→ 真实浏览器逐节点走查 + 截图 + AI 视觉评审 → 报告生成
2. **读报告**：编辑器弹窗/治理记录里看每节点判定；失败节点的 issues 会写明缺什么（如"狼群场景没有狼""姿态不符"）
3. **定向修复**（按报告原因）：
   - 缺角色立绘 → 聊天输入 `gamestudio 生成参考图 <项目id>` 补齐候选 → `gamestudio 锁定参考图 <项目id>` 锁定
   - 背景图不对 → 编辑器里对该场景重新出图（合成工作室场景属性→AI 生成分镜图）
   - 站位/姿态不对 → 编辑器右侧属性面板调整 placements（位置/缩放/上下场）
4. **再核实**：重复第 1 步；通过标准 = 全部节点图文匹配（verdict pass）
5. **导出终版**：核实通过后 `gamestudio 导出项目 <项目id>`（或编辑器导出按钮）

## 六、证据位置（可复查）

- 完整度报告与截图：`storage/projects/<项目id>/reviews/completeness*`
- 图片审核记录：`storage/projects/<项目id>/reviews/image_reviews.jsonl`
- 事件执行记录：守护台「项目事件」页每事件的历史
- 任务全程：治理页操作审计 + 会话列表

## 判定红线

- 任何「未通过」必须能追到具体节点与原因；不允许"看起来差不多就放行"
- 完整度核实 verdict=fail 时不得作为成品交付
