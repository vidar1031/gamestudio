# 小型互动故事画面表达优化实施方案

> 状态：实施提案，待项目负责人确认阶段优先级与测试故事。
> 目标产品：面向学生与年轻用户的 5–15 场景轻量互动故事创作、试玩与分享；后续扩展配音和短视频导出。
> 方案依据：截至 2026-10-08 的故事生产能力矩阵、近期生产验收与缺陷记录。本文不代表尚未实现的能力已上线。

## 1. 结论与产品定位

GameStudio 已具备生产并导出 5–15 场景互动故事的技术基础。已有 6 场景故事完成构图、场景背景、摆位、导出和双结局走查，也有 11 场景分层出图与可玩 H5 的生产记录。资产复用故事约 45 分钟完成创建到导出的记录，可作为流程效率参考，不是所有故事的交付时限承诺。

当前应定位为「轻量互动绘本/视觉小说创作工具」，而不是自动动画电影生成器。主要质量差距在故事事实映射、场景意图表达、角色/道具连续性、构图落地和视觉评审漏检，不是生产步骤能否串起来。自动化负责生成候选、暴露风险和降低重复劳动；关键画面由编辑预览与人工确认兜底。

建议分两条产品线推进：

- **互动故事主线**：分支文本、静态绘本画面、轻运镜、字幕、音效和可分享 H5。
- **宣传视频支线**：将已审核的互动故事路径导成线性短视频，配旁白、字幕、音乐和片尾链接。视频是引流内容，不替代互动故事本体。

## 2. 当前能力基线与边界

| 能力 | 截至本方案日期的判断 | 说明 |
|---|---|---|
| 5–15 场景故事生产 | 已具备流程基础 | 已有 6 与 11 场景全链记录；长故事仍需控制分支和独立视觉状态数 |
| 分支与 H5 导出 | 可用 | 已有双结局路径走查、可玩导出和体积控制记录 |
| 导演构图需求单 | 已实现基础版 | GS-49 提取状态、坐标、大小、层级、关系、镜头说明与原文依据，供摆位使用 |
| 运镜 | 有限 | 播放器有固定轻推近与淡入；`cameraNote` 目前不能视为可执行的完整镜头轨道 |
| 场景与资产一致性 | 有缺口 | Bible 场景引用错配和资产关联错误曾造成地点、道具跑偏 |
| 角色表演 | 有边界 | 姿势变体可用但成本更高；表情漂移、多人同框互动和动物姿势仍有未验证项 |
| 视觉质量自动评审 | 有帮助但不可靠到可单独放行 | 记录中出现过明显问题被高分误放；模型评分必须结合规则和人工抽检 |
| TTS、音频播放与成片导出 | 未验证为完整链路 | 设置中有 TTS 配置项；本提案不把它等同于逐节点配音或 MP4 导出能力 |

## 3. 实施原则

1. 以 6–10 场景、少量角色和少量地点作为默认创作甜区；15 场景是进阶上限，不是默认目标。
2. 用「视觉状态数」估算制作复杂度：同一角色在不同服装、姿态、表情、道具关系下的状态，通常比节点总数更能预测资产成本。
3. 每条生成结论可追溯到输入场景、资产计划、提示词、图片版本、评审和人工决定；不得把模型猜测写成剧情事实。
4. 先做低成本结构/内容验证，再决定是否调用模型出图；禁止因验证方便绕过正式生产工作流、审核门禁或任务留痕。
5. 评审采用「确定性规则 + 视觉模型意见 + 人工抽检」三类证据。任何单一 AI 分数都不作为全故事质量的充分证明。
6. 面向未成年用户时，默认适龄、隐私最小化；收集研究反馈须取得适当同意，不用未成年人敏感数据做定向画像。

## 4. 路线图与交付门槛

### 阶段 0：建立可重复的质量基线

**目标**：知道问题出在哪一层，并防止“导出成功”被误认为“故事表达成功”。

**实施内容**：

- 建立固定测试故事集及版本号；每次测试记录模型/提示词/风格预设/资产版本、随机种子（可用时）、耗时、失败与重试。
- 每个故事保留一份人工确认的结构真值：节点图、场景地点、出场角色/道具、路径条件、状态变化和必须出现的画面事实。
- 输出统一验收报告，分开记录结构、语义、视觉、运行时和体验结果；不以一个平均分遮盖硬错误。
- 复用现有完整度核实和审核证据，将截图、路径、评审、人工结论关联到同一轮测试。

**放行条件**：同一测试版本可由另一名操作者按文档复跑；证据能定位到具体场景和缺陷；失败明确标为 failed/blocked，不出现假完成。

### 阶段 1：补齐故事事实到场景的质量闸门

**目标**：先避免“故事写的是 A、Bible/资产计划/画面却是 B”。

**实施内容**：

- 为每个场景建立可检查清单：本场地点、必须出场角色、必须出现的关键物件、禁止误入元素、剧情状态、前后场景变化。
- 对照脚本、Bible `sceneRefs`、资产 `sceneIds`、构图需求单和实际 placements，报告冲突、缺项及无来源实体。
- 检查每个选择结果是否有可达后续节点、结局是否符合各自路径事实；合流场景不得写入只在单一路径发生的状态。
- 结构冲突在出图前阻断并给出可修复位置；不能用视觉模型替代结构校验。

**放行条件**：测试故事的关键地点与实体映射无冲突；所有分支可达且结局路径符合脚本真值；高严重度冲突不得进入批量出图。

### 阶段 2：把 GS-49 推进为可执行、可预览的轻导演

**目标**：让“导演”不仅写坐标，也能表达本场要让读者看见什么。

**建议的场景导演规格**（候选数据契约，实施时须兼容既有 `composition`）：

| 字段 | 用途 |
|---|---|
| `beat` | 本场剧情节拍：铺垫、发现、选择、行动、结果或情绪落点 |
| `visualIntent` | 本场应传达的情绪/信息，避免只复述抽象主题 |
| `focusSubjectId` | 第一视觉焦点 |
| `requiredSubjects` / `forbiddenSubjects` | 必须出现/不得出现的角色与物件 |
| `action` / `stateKey` | 可见动作与已登记状态；没有可靠动作资产时标记为静态近似，不假称动作已实现 |
| `shotSize` / `cameraAngle` | 景别和视角，选项用小而易懂的预设 |
| `cameraMove` | 从有限集合选择，如静止、轻推近、轻拉远；未支持的值须拒绝或回退并显式提示 |
| `blocking` | 元素相对位置、视线、接触/遮挡关系 |
| `captionSafeArea` | 字幕不得遮挡的重要区域 |
| `evidence` | 对应脚本原文，供用户核对推断来源 |

**界面建议**：延续当前编辑器结构，在场景管理/预览中呈现分镜卡和最终合成预览；常用项给人类可读的预设，坐标等高级参数仍可查看但不要求新用户理解。支持按选择路径连续预览，而不是只看孤立节点。编辑器预览与导出播放器共用同一套演绎参数，避免“编辑器看到的”和“导出效果”不同。

**放行条件**：每个镜头字段能映射到实际预览或明确标注为说明性文本；缺少动作变体时不伪装成动作；字幕不遮关键主体；结构化需求保存、刷新、导出后语义一致。

### 阶段 3：建立画面表达复核与定向修复闭环

**目标**：把检查从“图片存在且背景合格”扩展到“这幅图有没有讲对这一场”。

**检查分层**：

- **确定性检查**：引用文件存在、主体应出现且 placement 已绑定、角色数量、坐标越界、重叠风险、场景/地点 ID 对齐、字幕安全区、错误分支状态。
- **视觉模型辅助检查**：画面主体、动作可读性、地点/道具匹配、风格一致、角色外观连续、遮挡和构图问题；保留原图与逐项理由。
- **人工确认**：所有高风险场景及每故事至少抽查首场、关键转折、每种结局；模型与确定性检查意见冲突时必须人工裁决。

**修复规则**：缺地点/关键道具优先修 Bible 或资产关联，再重渲；站位/遮挡错误修 placement；角色动作错误换姿态变体或明确接受静态表达；不要一律靠重抽背景掩盖根因。修复前后保留版本和对比截图。

**放行条件**：严重错误为零；抽查路径实际走通；每个拒绝或人工特批有原因和证据；失败场景修复后复核同一检查项。

### 阶段 4：面向学生与年轻用户的创作体验试点

**目标**：验证用户能否理解故事、做出有意义选择并完成创作，而不只是生产系统能否跑完。

**试点任务**：给参与者一个短故事 brief，让其创建或试玩 6–8 场景作品；观察是否能理解选择、预测后果、读懂角色行动、找到修改画面的入口，以及是否愿意继续探索另一结局。

**观测项**：任务完成率、完成时间、无帮助完成比例、选择后果理解正确率、画面表达理解、卡点/误操作和主观兴趣（1–5 分）。少量参与者只用于发现可用性问题，不能声称代表市场结论。涉及未成年人时，需适当的监护人同意、告知与最小化记录，不采集不必要的身份信息。

**放行条件**：至少完成一轮问题归纳和修订复测；严重误解与阻断操作有处置结论；用户反馈与生成质量分开报告。

### 阶段 5：音频与宣传视频

**先做有声互动故事**：逐节点旁白/对白、角色与声音映射、可编辑音频、字幕时间、音效/背景音乐、静音和加载失败降级。先验证一个短故事从头到尾同步可听可读，再拓展批量生成。

**再做线性宣传视频**：由已审核的某一条分支路径生成竖屏视频草稿，支持时长/画幅、旁白、字幕、配乐音量、封面和片尾互动链接；导出前检查版权、字幕、音画同步、隐私及平台规格。视频不保留互动分支，应清楚引导观众进入网页玩完整故事。

**放行条件**：互动版与视频版共享经审核的文本和画面来源；音频失败不会导致故事不可玩；视频可完整播放、有可读字幕及正确片尾链接；授权信息可追踪。平台分发/变现政策需在上线前另行核实，不把平台收益作为技术验收项。

## 5. 推荐测试故事集

测试故事要覆盖不同的视觉表达问题，不能只用多个“主角站着讲故事”的样本。首轮建议 5 个，范围可按资产预算调整：

| 故事 | 建议规模 | 主要覆盖点 | 使用建议 |
|---|---:|---|---|
| 《狐狸与葡萄》 | 6–8 场景，1 主角，2 结局 | 欲望→尝试→失败→转折；朝向、跳跃/够取动作、葡萄关键道具；一个真实选择 | 现有长任务候选优先作为动作与物件表达基线；先确认其生产结果和权利来源，再纳入固定基线 |
| 《小猫钓鱼》 | 8–11 场景，1 主角，多道具 | 注意力转移、钓鱼动作、道具关系、因果和耐心主题；已有生产追踪可对照历史问题 | 用于历史回归，不把旧结果直接当质量金标准；先重标场景真值 |
| 《公主穿衣》 | 6 场景，2 角色，室内外/服装状态 | 服装阶段连续性、镜面近似、消息角色是否入画、双人结局和道具重复 | 作为导演语义与状态变体压力样本；保留此前人工修正前后对照 |
| 《三只小猪》 | 10–11 场景，多主角，多道具 | 群像尺度、角色区分、遮挡/重叠、房屋等场景道具、选择与结局差异 | 作为多人布场压力样本；当前多人同框质量不得预设已达标 |
| 原创《雨天的纸船》或同等原创校园/生活题材 | 6–8 场景，1–2 主角，2–3 地点 | 面向年轻用户的现代日常表达、情绪变化、视觉隐喻、原创性、移动端阅读 | 由团队创作并登记所有素材来源；避免只测经典童话的熟悉度效应 |

**分层执行以控制成本**：

1. 五个故事先全部做脚本、分支、Bible、资产/场景映射和构图规格的低成本检查。
2. 每个故事选首场、关键动作/转折场、结局场作为视觉样本；群像故事额外抽一场多人同框。逐图记录测试轮次，不只挑最好看的图。
3. 导演规格稳定后，对每个关键场景生成多个候选并盲评；至少做 3 次独立规划/构图重复，用来发现不稳定模式。这个次数是工程筛查，不足以证明统计可靠性。
4. 选定一轮完整故事走生产链、导出、真实浏览器路径走查；每种结局至少走一遍。后续如需宣称稳定性，再扩大重复轮次和参与者样本。

## 6. 验证与评分协议

### 6.1 硬门禁（任一失败即不通过）

- 所有预期场景与选择节点可达；每种结局均可到达且结局事实符合该路径。
- 所有背景、立绘、道具引用可加载；不得有空引用、破图或错误项目资源。
- 场景必须出场角色/关键道具缺失为零；错误地点或错误路径状态为零。
- 未审核的写入/导出不得绕过正式工作流和既有审核要求；测试失败必须留下 failed/blocked 证据。
- 儿童/学生试点内容符合适龄要求；不得使用未经授权的音乐、图片、角色或声音。

### 6.2 质量评分（分维度报告，不用总分掩盖缺陷）

每项以 0–4 评分：0=缺失/错误，1=明显妨碍理解，2=部分成立需修，3=清楚可用，4=表达准确且有感染力。人工评分附简短证据，不得只填数字。

| 维度 | 观察问题 | 首轮目标 |
|---|---|---:|
| 故事因果与选择意义 | 选择是否改变后续状态/结果，文本是否符合路径 | 均分 ≥3；硬性路径事实错误为 0 |
| 场景意图与画面可读性 | 不看制作提示时，画面能否表达本场动作/情绪/焦点 | 均分 ≥3；关键转折不得低于 2 |
| 实体与地点匹配 | 该出现的人/物/地点是否正确，是否混入不该有的元素 | 必需主体召回率 ≥95%；关键主体与地点错误为 0 |
| 连续性 | 角色身份、服装阶段、道具持有/状态是否连贯 | 均分 ≥3；关键状态冲突为 0 |
| 构图与字幕 | 主体层次清楚、无明显遮挡、字幕不压关键动作 | 均分 ≥3；严重遮挡为 0 |
| 试玩体验 | 用户能否理解操作和后果，是否愿意继续/重玩 | 记录量表与原话；先做基线，不预设市场通过线 |

首轮评分目标是工程基线，不等于上线标准。至少两位评审独立评关键视觉样本，分歧项记录理由后复核；对评分一致性做报告。若评审人数不足或样本过小，只能报告探索性结果，不能包装成客观市场验证。

### 6.3 可靠性判断

- **可重复执行**：固定故事版本、配置、提示词版本、资产版本和验证步骤；每轮有唯一 run ID 与可查 artifacts。
- **覆盖合理**：测试集覆盖单主角动作、多状态连续性、双人关系、群像遮挡、现代原创表达与分支结局，而非只覆盖一个成功案例。
- **测量可信**：硬错误用机器规则判定；语义/美术由盲评者按统一量表判定；AI 视觉评分先与人工标注集比较误报/漏报，再决定是否参与阻断。
- **稳定性有边界**：构图/视觉候选重复运行并报告均值、范围、成功率和失败类型。小样本只能发现问题，若要宣称某成功率具有统计置信度，需要预先设定目标区间并扩大样本。
- **链路完整**：脚本与节点图、Bible、资产计划、导演需求单、提示词、图像版本、AI 评审、人工决定、浏览器路径和导出包相互可追溯。

## 7. 每轮测试执行清单

1. 固定故事 brief、版本、目标年龄段、画风和互动公式；登记本轮 run ID。
2. 人工确认脚本真值表：节点/选择/路径、角色状态、地点、关键画面实体和结局事实。
3. 按正式故事工作流执行，不通过散调生成 API 取代生产链；阶段失败显式停止并留证。
4. 出图前检查 Bible、场景关联、资产计划和导演规格；高严重度不一致先修复。
5. 对规定样本场景收集全部候选，不隐藏失败候选；由盲评者与检查器分别评分。
6. 修复缺陷后重复同一场景检查，并进行全路径浏览器走查；交互、字幕和画面一起验。
7. 归档导出包、截图、报告、错误分类、修复前后差异、耗时和资源消耗。
8. 将缺陷分类为内容/关联/资产/构图/生成/评审/运行时/体验；只有复现、修复并通过回归后才关闭。

## 8. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 把导演 AI 分数当质量真值 | 使用人工标注样本校准；关键场景人工抽查；报告模型漏检 |
| 追求 15 场景导致分支和视觉状态爆炸 | 默认 6–10 场景；按状态数估算复杂度；限制重复生成与未必要的换装 |
| 静态立绘被误认为真实表演 | 用户界面明确区分静态演绎、姿势变体、动画；没有能力时给近似说明 |
| 只测经典故事而高估新用户表达 | 加原创现代生活故事并做试玩观察 |
| TTS/视频链路过早扩张 | 先完成互动故事质量闸门，再以独立阶段试点音频和视频 |
| 未成年人内容/隐私/素材授权风险 | 适龄审核、数据最小化、适当同意和授权记录前置到试点设计 |

## 9. 建议的近期决策

1. 批准阶段 0–3 为近期主线；先完成质量基线、事实映射闸门和导演规格闭环。
2. 首轮固定使用《狐狸与葡萄》《小猫钓鱼》《公主穿衣》《三只小猪》及一个原创现代生活故事；优先从低成本结构检查开始，不承诺一次跑完所有重型出图。
3. 明确 6–10 场景为默认产品甜区，15 场景列为进阶上限；题材复杂度由角色/地点/状态/分支共同估算。
4. 完成至少一轮工程回归和一轮小规模可用性试点后，再决定音频与短视频的 MVP 范围。
5. 每轮结论同步能力矩阵与缺陷记录；本提案本身不改变既有生产治理规则、审核门禁或存储真相源。
