# 多 Agent / 多模型自动化任务协作手册

本目录用于统一回答 3 个问题：
- 要干什么（目标）
- 如何干（流程与协议）
- 何时算完成（验收与门禁）

## 使用方式（自动执行活动）

1. 先写任务单：复制 `templates/TASK_TEMPLATE.md` 到新任务文件。
2. 再分配执行者：将完整的依赖链作为一次 execution campaign 交给主执行 Agent。
3. 主执行 Agent 按 `03-执行流程与状态机.md` 自动推进已满足前置条件的 task；每个 task 必须完成本地验收和自修复，但不需要人工逐 task 放行。
4. 主执行 Agent 在所有 task 完成、或遇到真实外部阻断时，提交一份 campaign 交付包。
5. 项目经理最后按 `04-验收门禁与放行标准.md` 对整个 campaign 做独立统一验收；验收失败时只退回有缺口的 task。
6. 验收完成后归档：将结果沉淀到任务单的“执行证据”和“复盘”章节。

## 当前执行入口

项目经理先阅读 `12-自动生产系统总实施与测试计划.md`，再按阶段门发起 campaign。`11` 说明架构定位；`12` 是实施与测试的唯一顺序规范。

当前 campaign 的起始任务：

- `tasks/TASK-HERMES-G01-memory-rebuild.md`
- `tasks/TASK-HERMES-G02-supervision-guard.md`
- `tasks/TASK-HERMES-G03-chat-submit-gate.md`
- `tasks/TASK-HERMES-G04-dead-route-cleanup.md`

阶段 0 后按 `12` 自动进入 A01-A02、B01-C01、C02-H03、E01-H04；任何阶段都不得绕过其测试门。

子 Agent 在每个 task 通过自身验收后可自动领取下一依赖 task；项目经理不逐 task 解锁，但会在 campaign 结束时独立复核，不能以子 Agent 自报完成作为最终放行依据。

## 统一约束

- 任务事实源优先级：代码与产物 > 日志 > 模型回答。
- 任何写操作必须可追溯：谁执行、何时执行、改了什么、为什么改。
- 未通过门禁，不得标记为完成。
- 模型输出是候选，不是事实。
