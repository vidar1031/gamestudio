# Kimi Code 免打断配置说明

## 目标

减少 Kimi Code 在长任务执行过程中反复弹出“yes, for this session”的中断。

## 已修改配置

1. `.qwen/settings.json`
- 已将权限从少量命令白名单扩展为项目级长任务白名单。
- 关键变更：加入 `Bash(*)`，并补充 `npm/node/git/rg/curl/find/sed/cat` 等常见命令。

2. `.qwen/settings.json.orig`
- 同步更新模板，避免后续脚本或人工回滚时把权限重新缩回。

## 这些中断会明显减少

- 子 Agent 运行脚本、测试、构建时的 Bash 命令确认。
- 常见研发命令（如 `npm run ...`、`git ...`、`node ...`、`rg ...`）导致的每会话反复确认。

## 仍可能出现提示的场景（属于安全硬门禁）

以下提示通常不是 `.qwen/settings.json` 能完全关闭的：

1. 写入工作区外路径。
2. 高风险删除或系统级操作。
3. 需要更高权限的网络/系统调用。
4. 终端沙箱策略触发的额外确认。

这些提示是保护机制，不建议完全关闭。

## 建议配合方式

1. 任务尽量约束在工作区内执行。
2. 子 Agent 避免执行无必要的高风险命令。
3. 使用任务单明确“允许命令范围”，减少临时扩权。
4. 仅在确有必要时才触发系统级操作。

## 回滚方式

如果你想恢复更严格权限：

1. 编辑 `.qwen/settings.json`，删除 `Bash(*)`。
2. 保留精确命令白名单（如 `Bash(npm *)`, `Bash(node *)`, `Bash(rg *)`）。

## 结论

- 本次修改可以显著降低“每个会话都要点 yes”频率。
- 不能也不应该绕过所有安全确认；安全硬门禁仍会在高风险操作时出现。
