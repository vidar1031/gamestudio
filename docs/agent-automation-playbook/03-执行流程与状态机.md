# 执行流程与状态机

## 1. 标准流程

1. Intake（接收需求）
2. Plan（拆解计划）
3. Execute（实施）
4. Verify（验证）
5. Gate（门禁判定）
6. Release/Archive（放行或归档）

## 2. 状态机

`queued -> running -> waiting_review -> passed -> archived`

失败分支：
- `running -> blocked`（依赖不可用）
- `running -> failed`（执行失败）
- `waiting_review -> failed`（验收不通过）
- `blocked/failed -> running`（恢复后重试）

## 3. 重试策略

- 瞬时错误：指数退避重试（1m, 3m, 10m，上限 3 次）。
- 逻辑错误：不自动重试，直接进入 failed。
- 环境错误：由 Recovery Agent 执行自愈动作后重试。

## 4. 超时策略

- 每个步骤必须有 timeout。
- 超时后立即写入错误证据并进入 blocked 或 failed。

## 5. 幂等要求

- 每个步骤必须支持重复执行。
- 重试前先检查是否已成功落盘，避免重复写坏状态。
