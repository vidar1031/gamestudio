# 交互优化升级方案

> 范围：TalkScene（织话智坊）全部人接触面——编辑器（React+PixiJS）、守护台 console（Vue3）、文档站（docsys）。
> 输入源：编辑器契约（四区）、《系统生产级推进方案》UI 约束、《UI 设计规范》（ext_UI设计规范，本方案所有波次的前置规则）、`docs/UI_REDESIGN_PROPOSAL.md`（已部分实施）、模块化拆分完成态、生产实测事故记录。
> 前置声明：TalkScene 是小团队/个人**本地部署**的创作工具，文本/图像/语音/视频模型矩阵可配置是其差异化卖点——**设置是一等功能区**；本方案任何波次不得削弱模型可配置性（完整定位见《UI 设计规范》§1）。
> 写作纪律：方案恒常化，不绑具体案例。

## 1. 现状诊断（证据先行）

| 症状 | 证据 |
|---|---|
| 观感失序 | 首页卡片与栏位堆叠、挤压；间距无阶逐处手写；密度忽松忽紧（2026-10-20 首页实测） |
| 文案寄存器混排 | 测试/调试文字（运行检测、诊断日志、测试连接）与面向用户文案同屏共存；英文残留按钮；状态串为内部口径（"可玩 ↗ · 10 卡 / 10 节点"） |
| 删除文案张冠李戴 | 删除整个项目弹窗标题为"删除故事草稿"（Hub.tsx 复制残留，已登记为首页整改波必修缺陷） |
| 主流程巨弹窗 | "AI 生成新故事"以全屏弹窗承载主流程；设置页所有分区一屏平铺 |
| 无自适应 | 列表固定栅格写死，无断点规则，窄屏布局失序 |
| 双界面分裂 | 生产操作在编辑器弹窗/向导，审核监控在守护台——用户被迫两边跳；真实生产全程由会话+台账驱动时，编辑器弹窗链零使用 |
| 弹窗套弹窗 | AI 抽卡/姿势池/设置/正式出图管理多层模态互压（z-index 战争有实测记录） |
| 向导硬编码后端状态机 | 锁定事物七步向导在 UI 层写死步骤序，与服务端出图总账重复表达同一事实，历史多次不一致事故 |
| 巨型页面组件 | ComposeStudio.tsx ~12.8k 行（画布+编排+属性+弹窗全部内联）；Hub.tsx ~1.9k 行（创建弹窗+草稿箱+项目卡+设置入口内联） |
| 设计系统缺失 | 组件状态/徽标/间距各页自定，深色基底+单一强调色约束未成 token 体系 |
| 编辑器巨页与守护台多页信息重复 | 审核记录/台账/进度在两界面各画一遍 |

## 2. 优化目标与原则

**目标**：创作者单界面完成生产操作，守护台专注治理监控；交互形态跟随服务端真相源状态机，不再 UI 侧另写流程。

**原则**（守既有契约）：
1. 四区布局语义保留（顶=全局、左=结构、中=画布、右=属性）；右栏仍是唯一编辑入口。
2. 深色基底+单一强调色；组件状态 default/hover/active 三态。
3. 文案面向用户；未配置 Provider 的动作明确阻断。
4. 绞杀者模式：新交互并行生长，旧形态冻结后退役；每波有截图基线对照。
5. 整理与功能不混提（Tidy First）；交互改版与改名/拆分各自独立成波。

## 3. 方案（按信息架构分层）

### 3.1 信息架构（IA）重划
- **编辑器 = 创作台**（制作与微调）：项目库 → 工作台（结构树/画布/属性）→ 导出。
- **守护台 = 驾驶舱**（生产驱动与治理）：会话发起、任务队列、审核批准、资源与审计。
- 唯一事实流：台账/审核/进度由服务端供给，两界面只呈现不复制逻辑。

### 3.2 编辑器外壳：弹窗群 → 项目工作台单页
0. 波 0 首页（项目库）观感整改：间距阶与流式栅格落地、卡片信息序与操作菜单规范化、状态文案映射表上线、删除文案缺陷修复、新建流程页内化（一句话创意为主，公式/模板折叠进高级）、设置改为独立页面并按《UI 设计规范》§6 分区。封面墙非本波必须项（2026-10-20 负责人裁决）。
1. 波 1 骨架：左栏故事结构树（场景/资产合一树），中栏画布+任务时间线（台账实时流内嵌，消灭黑盒弹窗），右栏属性/审核二合一（选中即所审）。
2. 波 2 向导解体：锁定事物七步向导退化为资产卡片的内联状态机——候选池/评审分/锁定/线稿/变体全部落在卡片上（卡片状态=服务端 referenceStatus/lineartStatus 直读，不另存 UI 流程态）。
3. 波 3 ComposeStudio 拆分：canvas（Pixi 舞台）/orchestration（编排操作）/panels（右栏属性族）三模块；编辑器命令单向数据流（dispatch→store→画布重绘），消灭 Pixi  imperative 与 React 状态混写。
4. 波 4 旧壳冻结公告：弹窗族只收缺陷修复。

### 3.3 审核与评审体验（质量闭环的操作面）
- 审核入口统一内联：候选卡/场景卡/变体卡上就地呈现分数+问题清单+「按意见重抽/修复」按钮（issues 合入重抽提示词）。
- 三级门禁（出图前/锁定/场景绑定）在所有界面同形同义；待审队列在编辑器与守护台同源呈现（同一份 API 数据，不各自拉取加工）。
- 低分候选：提示+用户确认特批（保留 manualOverride 留痕语义），不强制阻断。

### 3.4 画布（编排器）体验专项
- 既有能力保留：像素级命中、拖放/缩放/层级/翻转/撤销、编辑预览双模。
- 升级点：对象吸附对齐线（同排元素对齐引导）、状态变体切换器（摆位上直接切换剧情状态）、场景间快速跳转条（节点导航面包屑）。

### 3.5 守护台收敛
- 十三页合并为四区：任务（队列+会话时间线合一）、审核（图片+步骤+治理审计）、资源（模型/调度/出图状态）、系统（诊断/设置/文档）。
- 任务卡片即操作面板（取消/恢复/重试内联），不再跳页。

### 3.6 设计系统落地（design tokens）
- 建 tokens 层：颜色（基底/面板/线/正文/弱文/强调）、间距阶、圆角、徽标三档色（绿/黄/红）、字号阶；编辑器与守护台共用同一份 token 定义。
- 组件库最小集：卡片/徽标/按钮/输入/表格/折叠区/吐司/进度条——两界面各自实现但同 token 同状态语义。
- docsys 站点即参照实现（已是深色基底+单一强调色）。

### 3.7 可达性与反馈
- 一切长操作有进度条与可取消；一切失败给原因+下一步建议；禁止静默失败（与接口纪律同源）。
- 键盘流：画布撤销/删除/方向微调；表单全键盘可达。

## 4. 实施波次与验证

| 波 | 内容 | 验证门 |
|---|---|---|
| U0 | 设计 tokens+组件基线页（两界面各一参照页）+截图基线库（含三档断点） | 基线页截图入库；探针跑通 |
| U0.5 | 首页观感整改（=§3.2 波 0） | 《UI 设计规范》§9 逐条自查通过 + 三档断点截图对照 |
| U1 | 编辑器工作台骨架（只读浏览先通） | 真实项目只读回归零差异 |
| U2 | 向导解体为卡片状态机 | 生产链实测：抽卡→锁定→线稿全程在卡片完成 |
| U3 | ComposeStudio 拆分+单向数据流 | 画布操作探针（拖入/缩放/撤销/落盘回读） |
| U4 | 审核内联化+同源呈现 | 三级门禁两界面同源数据一致实证 |
| U5 | 守护台四区收敛 | 操作任务全链路在收敛页完成 |

每波：截图基线对照 + typecheck + 业务面/控制面测试全绿 + 真实项目走查不回归。

## 5. 验收口径（升级完成定义）
- 创作者从项目库到导出可玩包全程不离开编辑器工作台（零弹窗跳转）。
- 操作员在守护台完成一切审核与处置（零切编辑器）。
- 弹窗族退役；组件状态三态一致；tokens 单一来源。
- 走查+探针+基线对照全绿。

## 6. 与其它线的关系
- 依赖工程线：P0 基线波（截图基线库）先行；ComposeStudio 拆分与 U3 同波合并。
- 不改生产链语义：本方案只动交互外壳；审核门禁/真相源/调度语义全部不动。
- 命名已落地（TalkScene/织话智坊）：本方案实施时 UI 文案用新名。
