# 数据要求说明书

> 范围：系统静态/动态数据的逻辑描述、采集要求与数据约定。字段级字典见《数据库设计说明书》。

## 1. 引言

### 1.1 编写目的
规定织话智坊系统数据的构成、来源、流向与约定，作为数据设计（07）与接口设计的输入。

### 1.2 背景
系统为纯文件真相源架构：无传统数据库，全部生产状态以 JSON/JSONL/图像文件存于项目自包含目录；配置与模板另有全局存储。

### 1.3 定义与参考资料
见《概要设计说明书》§6、《软件需求说明书》§3.4。

## 2. 数据的逻辑描述

### 2.1 静态数据
- schema 契约类型：ProjectV1/StoryV1/NodeV1/CharacterV1/AssetV1/BlueprintDocV1/ScriptDocV1 等（packages/schema 定义，构建期类型检查）。
- 工艺件库：载体/动作技能件定义（craftLibrary：技能 id/类别/模板/负向词）。
- 风格预设：出图风格样本（checkpoint/LoRA 栈/风格句/排除词/尺寸剖面/审核链/压缩策略）。
- 全局设置：供应商/模型/翻译/评审/图像通道配置。

### 2.2 动态输入数据
- 用户输入：创意文本、题材配置、提示词中文稿、审核批准/拒绝、特批指令、编辑操作（拖放/属性修改）。
- 外部输入（可选）：云端评审/翻译响应（必须有本地兜底）。

### 2.3 动态输出数据
- 生成中间件：脚本/圣经/计划/状态表/提示词/候选图/线稿/变体图/背景图。
- 决策记录：三级审核记录、评审分与问题清单、台账条目、治理审计、reasoning 事件流。
- 交付物：H5 导出包、（规划项）预演视频与演示录制。

### 2.4 内部生成数据
- 出图总账（coverage 聚合视图）、构图需求单（plan.scenes[].composition）、摆位（story.json visuals.placements）、创作缓冲（journal.jsonl+快照）。

### 2.5 数据约定
- 标识：资产/变体/任务/会话均以 `前缀_时间戳_随机` 形式生成唯一 id；sceneId 即故事节点 id。
- 键值：poseKey/stateKey 为变体登记键（摆位按此命中）；技能件以 skillId 索引；合并唯一键：generatedRefs=projectAssetUri、poseCandidates=assetPath、poseVariants=id。
- 语言：提示词一律先中文稿批准后经翻译链产出英文；锚点字段（anchorPrompt/referencePromptEn）保持英文。
- 数值域：摆位 x/y∈[0,1]、scale∈[0.1,2.5]、zIndex∈[1,99]；评审分 0–100；压缩质量分档固定（无损/90/92）。
- 保密：API 密钥仅存 .env 类文件，不入库不入日志。

## 3. 数据的采集

### 3.1 要求和范围
- 采集即落盘：任何生成/编辑动作即时写真相源，禁止只驻内存；写前快照自动轮转。
- 合并语义：计划保存走"读取-合并-写入"（记录数组按键并集、声明键允许入站更新），并发写以 _rev 乐观锁裁决。

### 3.2 输入的承担者
- 创作者：编辑器内一切输入；操作者：守护台审核与处置；系统：调度器/看门狗的自动处置（全部留审计）。

### 3.3 预处理
- 模型产出须经确定性加工（拟合/校验/翻译/评审）方可落真相源；模型输出只是候选，不是事实。

### 3.4 影响
- 真相源体积随生产增长（图像为主）：出图即压三档策略约束体积；导出包 ≤5MB 为交付硬约束；retention 定期归档运行历史。
