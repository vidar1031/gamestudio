# UI 设计规范（规则声明）

> 类型：规则规划声明——先于实施的裁决文档。与《交互优化升级方案》是"规则—波次"关系：本规范定义"什么样算对"，升级方案定义"分几波做到"。一切界面新建/整改/缺陷修复必须先过本规范，再谈实现。
> 适用：TalkScene（织话智坊）全部人接触面——编辑器（React+PixiJS）、守护台 console（Vue3）、docsys 站点、导出物内的运行时 UI。

## 1. 产品定位前置声明（一切 UI 裁决的前提）

1. TalkScene 是小团队/个人**本地部署**的创作工具，不是在线大模型服务。差异化在"本地可控"：文本模型、图像生成模型、语音模型、视频模型等 AI 能力全部由用户自行配置、自行替换。
2. 双重受众：**创作者**（用工具产出作品）与**二次开发者**（读代码、改模块、接接口）。界面命名、文档写法同时服务两类人。
3. 推论一：**设置是一等功能区**。它承载模型矩阵配置，是本产品存在的理由之一，不得简化为"高级选项"，不得下沉到别的界面；但设置页自身必须遵守 §6 的分区与文案纪律。
4. 推论二：界面默认假定**单机本地运行**。不出现"额度/套餐/账号/云端同步"等在线服务语义；本地资源消耗如实说"占用本机内存/出图约需 X 分钟"；仅当某能力确走外部计费 API（如自配的外部 Key）时才允许"计费/额度"措辞，且必须标注对象。
5. 推论三：**本地部署 ≠ 免工程化**。观感、文案、自适应按市场发行软件标准验收，不按内部工具标准验收。

## 2. 观感纪律（严谨性）

现状病灶（2026-10-20 首页实测）：卡片与栏位**堆叠、挤压**；间距凭感觉逐处手写；信息密度忽松忽紧。规则：

1. **间距有阶**：只允许使用间距阶 `{4, 8, 12, 16, 24, 32}`（px），禁止手写任意值；卡片内边距统一 16，卡片间距统一 16，栏间距统一 24。
2. **对齐成网**：同区元素左边缘必须共线；卡片网格列宽由容器算（流式栅格），禁止逐卡写死宽度。
3. **密度一致**：同一列表内卡片等高；标题、状态行、时间行位置逐卡一致，禁止因内容有无而移位（无内容显示占位，不撤行）。
4. **层级最多三层**：页面背景 / 卡片面板 / 卡内强调区，禁止第四层浮起；弹窗只允许一层（见 §7）。
5. 颜色、圆角、字号阶、徽标三档色（绿/黄/红）以 design tokens 单一来源（U0 波落地）；令牌分层、数值基线、换肤与多语言机制见《设计令牌与主题扩展规范》（ext_设计令牌与主题规范），tokens 未落地前，新样式先按该规范数值写死在同名 CSS 变量里，禁止散落魔法数。

## 3. 文案纪律（三个寄存器，禁止混排）

| 寄存器 | 出现在哪 | 规则 |
|---|---|---|
| 用户语言 | 界面默认可见的一切文字 | 创作者看得懂的动作与结果（"已完成 · 可导出"）；不出现内部名词 |
| 技术语言 | 折叠区、"高级/诊断"入口之内 | 允许出现 provider/model/端口等，但必须成行成组、有标题 |
| 测试/调试文字 | **禁止出现在任何生产界面** | 开发期探针、临时占位、TODO 文案一律不得合入 |

硬规则：

1. 界面默认只讲用户语言；技术语言必须折叠且默闭合。
2. 禁止研发术语外露：内部流水线名、版本代号、优先级代号、英文残留按钮（如 Clear）一律中文化或移除。
3. 状态文案走"内部状态 → 用户语言"映射表（单一来源，全端共用）；禁止在各页面各自拼接状态串。
4. 时间一律相对化（"3 天前""昨天"），悬停才给精确时间。
5. 说明性长文（教用户怎么用）收进右栏说明区或帮助页，卡片与按钮上不写说明书。

## 4. 自适应规范（全站强制）

1. 适配区间：1280×720 起步至 4K；1280 以下允许横向滚动但不允许布局破碎。
2. 断点三档：`≥1440` 三栏（左结构/中主区/右说明）；`1024–1440` 两栏（右栏折叠为可展开抽屉）；`<1024` 单栏（右栏、左栏皆抽屉化）。
3. 列表栅格流式：卡片最小宽 280，容器够宽才加列，禁止固定三列写死。
4. 画布区（Pixi）自适应剩余空间，缩放控件常驻；右栏属性在窄屏转为底部抽屉。
5. 验收：三档断点截图入基线库，每波次对照（与 U0 截图基线合并执行）。

## 5. 列表与卡片规范（项目库等一切列表通用）

1. 列表工具条（搜索/排序/筛选）**可以有**：固定在列表上方一行，左搜索右排序筛选；样式走 tokens，不得临时拼样式。
2. 卡片信息序固定：标题 → 状态行（用户语言）→ 相对时间；主操作一个（继续制作），其余进卡片角标菜单。
3. 危险操作必须二次确认，且**文案与对象一致**（删项目说项目、删草稿说草稿——当前删项目弹"删除故事草稿"为已登记缺陷，首页整改波必修）。
4. 空态：低频功能区（如草稿箱）为空时折叠为列表内一行条目，不占独立大卡。
5. 封面：非首期必须项；若做，取项目自有产物图，规格统一 16:9 裁切，缺图用占位纹。

## 6. 设置页规范（一等功能区）

1. 分区固定为五区：**模型矩阵**（文本/图像/语音/视频各一卡，provider+模型+地址+连通状态）、**接口 Key**（按服务商分组，显示/清空/来源标注）、**网络**（代理）、**出图与生成参数**、**诊断**（快速检测、运行日志——本区允许技术语言）。
2. 页首置"当前生效"只读摘要条：各域 provider / model 一行一个，格式统一 `provider / model`。
3. 每区一折叠卡，默开展示模型矩阵，其余默认收起；禁止所有分区一屏平铺（当前设置弹窗的平铺堆叠即病灶）。
4. 未配置 Provider 的动作必须明确阻断并给配置入口，不得静默失败（沿用既有契约）。
5. 设置从全屏弹窗改为独立页面（路由可达），守护台设置区只放治理侧配置，两边不互相复制。

## 7. 弹窗与页面层级规范

1. 主流程（新建故事、锁定事物、场景出图）**页内化或半屏抽屉化**，禁止全屏表单弹窗遮罩列表（当前"AI 生成新故事"即病灶）。
2. 弹窗全局同时最多一层；确认框是唯一允许的二级浮层。
3. 弹窗尺寸三档：确认（≤420）/ 表单（≤720）/ 检视（≤1080）；禁止超出。

## 8. 右栏（说明/状态区）规范

1. 右栏可以保留，但必须有固定分区结构：说明 / 环境状态 / 最近动态，各区有标题、可折叠、空态折叠。
2. 环境状态属技术语言寄存器：默认收起，展开后成行成组。
3. 右栏宽度定档（320），窄屏按 §4 抽屉化；禁止挤压主区。

## 9. 验收口径

- 任一界面整改或新建：先对照本规范逐条自查，再过《交互优化升级方案》对应波次验证门。
- 三档断点截图 + 文案寄存器抽查（默认视图零技术语言、零测试文字）+ 间距阶抽查（无魔法数）。
- 本规范与 tokens（U0）同步落地；tokens 未就位前的临时实现必须在代码中标注对应规范条目号。

## 10. 图标与分割线（2026-10-20 补）

1. **图标**：一律 16px 内联 SVG（1.5 描边、currentColor、圆角端点），语义化命名、集中管理（首个实例：`apps/editor/src/settings/icons.tsx`）；图标随文字色，hover 可走单一强调色；禁止引入图片图标与第三方图标库。
2. **分割线三级制**：分区标题下主分隔 `rgba(148,163,184,.14)` / 展开卡头与卡体之间 `.10` / 卡内相邻行细分隔 `.08`；只允许这三档透明度，禁止更重的线（tokens 落地后归 `--ts-border*`）。
3. **折叠控件**：必须是真按钮（可聚焦、`aria-expanded`），chevron 图标 + 文字（展开 ▸ / 收起 ▾ 旋转）；卡片头其余区域点击亦可折叠，两者行为一致；**禁止把折叠触发器放进 stopPropagation 容器**（设置页实测缺陷：点了无反应）。
