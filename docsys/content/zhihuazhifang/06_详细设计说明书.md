# 详细设计说明书

> 范围：创作故事生产链逐模块的实现逻辑（输入/处理/输出/算法要点/接口/测试要点）+ 产品 UI 设计规格。
> 与概要设计的关系：概要定层与边界，本说明定模块内部机制；模块名与概要设计 §4 目录对应。
> 写作纪律：描述恒常机制，不记具体案例名与任务代号。

## 1. 引言

### 1.1 编写目的
使工程开发、测试与接手人员能在不读全量源码的前提下，理解每个模块"输入什么、怎么处理、输出什么、为什么这样设计"。

### 1.2 背景
生产链分十一个主模块（M1–M11），按数据流顺序衔接；另有四个横切模块（X1 调度租约/X2 审核门禁/X3 台账/X4 UI 规格）。

### 1.3 定义与参考资料
见《概要设计说明书》、《软件需求说明书》、编辑器契约文档。

## 2. 程序系统的结构


## 3. 模块设计说明

### 3.1 M1 脚本生成（ai/scripts.js）
- **功能**：自然语言创意→公式化脚本（结构公式：场景数/选择点数可配）。
- **输入**：创意文本、题材配置（受众/风格/语言）、结构公式。
- **处理**：LLM 按公式指令生成→确定性拟合（fitScriptCardsToFormula：场景拆分、选择点补齐、节点 id 规范）→结构校验。
- **输出**：scripts.json（节点/分支/文本）。
- **算法要点**：公式优先于自由发挥——模型产出后由确定性代码修正结构，保证可编译。
- **测试要点**：拟合后结构校验零 issue；选择点可双分支推进。

### 3.2 M2 圣经与质检（ai/storyBible.js + storyBibleQc.js）
- **功能**：生成故事圣经（角色/设定/规则/台词基调/叙事约束）并质检修正。
- **处理**：按字段分块生成（降 max_tokens 护栏）→质检（sceneRefs 校验、绑定修正）→persist 落盘；修正后作废旧资产计划（计划随后重建）。
- **设计理由**：圣经是资产计划与场景设定的上游，错误必须在此拦截。
- **测试要点**：五要素齐全；质检 persist 后引用一致。

### 3.3 M3 资产计划（ai/storyAssets.js）
- **功能**：从圣经提取事物/场景/地点锚点，去重合并，建立场景↔资产归属。
- **处理**：模型提取→确定性去重（名称/别名 fuzzy 匹配）→repair-links 场景关联修复（子串/别名证据）→风格预设解析（resolveStoryStylePreset）。
- **输出**：plan.json（assets/scenes/globalPrompt 等）。
- **测试要点**：归属完整率；风格预设字段全链路透传不丢。

### 3.4 M4 提示词管理
- **功能**：全局与专属提示词的中文起草→翻译→批准链。
- **处理**：中文稿先确认→翻译链（translate.js，严格 JSON 失败退宽松解析再退纯文本）→英文批准后才允许进入抽图。
- **纪律**：先中文确认后英文批准，顺序不可绕过；批准后才进抽图阶段。

### 3.5 M5 参考图与锁定（ai/storyLock.js + storyAssetReferenceGate.js）
- **功能**：逐资产抽卡→AI 视觉评审→人工确认锁定→主参考写回。
- **处理**：候选生成（负向排除多视图/设计稿/带环境）→评审（身份/画风/背景三档）→锁定（三级门禁：出图前 pre_generate、锁定确认 lock_confirm、特批 manualOverride 留痕）。
- **测试要点**：低分候选被拦（可提示后用户确认特批）；写回即补 lock_confirm 记录。

### 3.6 M6 线稿
- **功能**：ControlNet 从主参考生成线稿（ControlNet Hint + Final Lineart）。
- **设计理由**：线稿是后续姿势变体的结构约束来源；跳过需明示。

### 3.7 M7 状态提取与变体（storyStates/storyPoseStates/storyPropStates/craftLibrary/states-generate 编排）
- **功能**：剧情状态表提取→按缺口生成姿势/载体/道具状态变体→登记带键→摆位上场。
- **处理**：
  1. 提取：模型逐场景产出每资产状态（stateKey/label/evidence/relatedAssetIds）；
  2. 缺口计算：findStateGaps（poseVariants+stateVariants 双池按 stateKey/poseKey 匹配，支持 sceneId 过滤）；
  3. 生成编排（states/generate 串行）：角色姿态走绿幕出图+抠图+登记；载体走工艺件模板填槽（锚点英文化、单人净化、场景域=需求场景）；道具状态按"容器+内容物"走确定性合成（fill_composite：多叠加层槽位接续防重叠、名称分档大小、亮度还原），非容器回退 AI；
  4. 登记：poseKey/stateKey 写回（mergeRecordUpdates 通道，防既有记录更新被合并丢弃）。
- **测试要点**：缺口归零可复算；中断任务不得按成功计；空手/多人变体不得过验收门。

### 3.8 M8 导演构图与摆位（storyComposition.js + placements 端点族）
- **功能**：构图需求单→确定性摆位写回 story.json。
- **处理**：构图 LLM 按工艺目录选件（含 stateKey）→摆位计算：状态变体优先（viaStateKey）、载体承载道具撤除独立摆位（covered_by_state_variant/carrier 含历史摆位确定性移除）、表情差分兜底、人工摆位保留（幂等刷新仅更新引用）。
- **测试要点**：同一角色多状态在同场景区正确；被承载道具零双重影像。

### 3.9 M9 场景出图与绑定（background.js + sceneBackgroundReview.js）
- **功能**：纯环境背景出图→AI 视觉评审→绑定。
- **处理**：背景 prompt 由非角色资产英文锚点+地点锚点构成（禁叙事文本防人物烤入）→评审（纯环境/锚点匹配/画风一致，fail-closed）→绑定写 story.json（scene_bind 留痕）；失败换种子重渲一次，仍败显式阻断。
- **测试要点**：背景无人物烤入；评审不可用挂 pending 不盲批。

### 3.10 M10 校验导出（blueprint/ + plugins/storyPixi.js）
- **功能**：脚本→蓝图→可运行故事编译；引用收集+压缩导出。
- **处理**：编译双段（脚本→蓝图→compose）；导出收集 placements/背景/字幕引用→分层压缩（≤5MB 目标）→运行时打包。
- **测试要点**：导出包无头实测零 console 错误。

### 3.11 M11 走查与完整度（storyWalkthrough.js + storyCompleteness.js + storyCoverage.js）
- **功能**：全结局路径枚举走查（截图+文本一致性）、完整度逐节点画面核实、出图总账聚合。
- **处理**：确定性路径枚举→逐节点截图与文本核对→报告落盘；总账从 plan/story/project/reviews+磁盘事实聚合完成度。
- **测试要点**：走查报告可映射回 sceneId；总账与磁盘一致。

## 4. 横切模块

### 4.1 X1 调度租约（control resourceScheduler + 业务面 resourceLease）
三槽 reader-writer（llm 共享/vision、gpu 独占）；gpu 申请触发卸载→验证→放行序列；交换失败显式；孤儿租约随控制面重启清空；settle 窗口攒批。业务面所有本地模型/出图调用必须先取租约，控制面不可达即阻断。

### 4.2 X2 审核门禁
三级图片审核（pre_generate/lock_confirm/scene_bind）+ 会话步骤级审核；托管自动批准经同一通道（留审计）；`off` 旁路只免人工门禁，AI 评审 fail-closed 照常。

### 4.3 X3 台账（createAiTask/updateAiTask）
一切长任务（抽卡/锁定/线稿/变体/场景渲染/批量）建台账条目：stage/current/total/message/result；中断标 interrupted；轮询按 taskId 精确命中。

### 4.4 X4 UI 设计规格

#### 4.4.1 设计原则
- 编辑器契约：**对象优先于数据，结构优先于视觉**；严格四区布局——顶部（全局行为）、左侧（结构管理）、中央（画布预览）、右侧（属性编辑，唯一编辑入口，禁止同字段多处出现）。
- 视觉纪律：深色基底 + 单一强调色（#5eccff）；组件状态仅 default/hover/active 三种；文案面向用户，不出现研发术语；Provider/Model 显示格式统一 `provider / model`；未配置 Provider 的动作必须明确阻断。

#### 4.4.2 页面与交互流程
| 界面 | 构成 | 关键交互 |
|---|---|---|
| 项目库 Hub | 卡片画廊+迷你阶段轨+可玩徽标 | 继续上次/新建（一句话创意→草稿） |
| 脚本工作室 | 左结构/中文本/右属性 | 节点增删改、公式重拟合 |
| 蓝图工作室 | 节点图 | 编译检查、分支审阅 |
| 合成工作室 | 场景编排器（Pixi 画布）+右栏属性 | 拖放/缩放/层级/翻转/撤销/像素级命中/编辑预览双模 |
| 锁定工作台 | 步骤流+候选池+评审分 | 抽卡/再抽/AI 评审/特批/线稿/变体 |
| 守护台 console | 任务队列/会话时间线/审核卡片/资源状态/治理审计 | 会话发起、批准/拒绝、取消/恢复/重试 |
| 弹窗族 | AI 抽卡/姿势池/设置/正式出图管理 | 弹窗内独立进度条，禁止黑盒 |

#### 4.4.3 组件与状态规格
- 候选卡：默认/悬停/选定/评审徽标（≥70 绿、40–69 黄、<40 红）。
- 审核卡：待审（常显顶部）/批准/拒绝，内联处理，批准后自动跟进下一步。
- 台账条：stage 名+current/total+消息；中断红色标记。
- 编排器选中：高亮框+四角缩放手柄+双击开动作立绘。

#### 4.4.4 待改方向（登记）
弹窗套弹窗与双界面分裂已定为工程线改造对象（工作台聚合方向，详见《工程升级实施方案》）；本规格届时整体修订。

## 5. 测试计划要点（模块级）
每模块配：正常路径用例+边界用例（空/极端/并发写）+故障用例（通道不可用/中断恢复）；核心算法（拟合/缺口/摆位命中/合并语义）必须有不依赖出图的确定性单测或脚本验证。
