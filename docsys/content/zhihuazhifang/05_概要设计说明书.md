# 概要设计说明书

> 范围：系统总体结构、工程目录、前后端框架、模块划分、接口设计、运行设计、数据结构设计、出错处理设计。模块级施工细节见《详细设计说明书》。
> 写作纪律（全局统筹层）：只描述架构与机制的恒常形态，不记具体案例名与任务代号。

## 1. 引言

### 1.1 编写目的
确立织话智坊系统的总体设计基线，使工程开发、测试、评审与接手人员对系统分层、模块边界、接口与运行方式有一致理解。

### 1.2 背景
系统为双平面格局：业务面（本仓：编辑器+业务后端+共享包）承载生产与交付；控制面（local-agent-control 仓：守护台后端+守护台前端）承载编排、审核、调度与治理。两平面经 HTTP 租约、事件分发、审核代理耦合。

### 1.2.1 双平面定位声明（2026-10-20 负责人确认）

1. **业务平面（talkscene 仓）是自足的互动故事生产工具**：编辑器 + 业务后端独立承载全部生产链（创意→脚本→蓝图→合成→校验→导出）。脱离守护台运行时，TalkScene 是**全手动 UI 交互式生成工具**——一切动作由人操作编辑器驱动。
2. **控制平面（local-agent-control 仓）是守护台**：AI 模型的中间管理层（模型路由、三槽资源互斥、审核门禁、看门狗、托管审批）+ 自动化生产驱动层（交互式会话 → 事件分发 → 驱动业务面执行，自动审核、自动跑完全程）。
3. **守护台不是准入后端**：业务面的项目读写、编辑、编译、导出不经过守护台；守护台故障不影响纯编辑与本地文件操作。
4. **独立运行边界**：重负载本地资源调用（文本生成/出图/视觉评审）默认经守护台资源租约，守护台离线时 fail-closed 阻断（保护本机内存墙）；无守护台的独立手动模式须显式设置 `STUDIO_RESOURCE_LEASE_ENABLED=false`。

### 1.3 定义
真相源：项目存储目录（plan/story/project/states/reviews）。租约：资源调度互斥令牌。三级审核：出图前/锁定确认/场景绑定。台账：/ai/tasks 长任务进度。

### 1.4 参考资料
《软件需求说明书》、编辑器契约文档、控制面架构说明文档、《系统生产级推进方案》。

## 2. 总体设计

### 2.1 需求规定
见《软件需求说明书》§3 全部条目；本章给出承载它们的结构。

### 2.2 运行环境
Apple Silicon 32G；Node.js 18+（ES Modules）；本地模型服务（OMLX :18888）；本地出图服务（ComfyUI :8188）；浏览器（Chrome 系）。

### 2.3 基本设计概念和处理流程
设计概念：**真相源为中心 + 双平面 + 全链可观测**。所有生产状态落盘为文件真相源；控制面只编排与治理，业务面只生产与交付；一切长任务经台账暴露，一切敏感动作经审核门禁。

```chart flow
A: 自然语言创意
B: 守护台分步计划
C: 业务面逐步执行
D: 真相源落盘
E: 审核门禁
F: 交付物
A -> B -> C -> D
C -> E -> C
D -> F
```

### 2.4 结构（系统分层）

```chart layers
L8 交付层：导出构建插件（引用收集+压缩）、可玩 H5 运行时
L7 交互层：编辑器四工作室与编排器、守护台 console 十三页
L6 治理层：三级图片审核、审图中心、托管审批、治理审计
L5 编排层：reasoning 会话、持久化队列、看门狗、工作流注册表
L4 调度层：资源互斥调度器（文本/视觉/出图三槽，换入换出）
L3 生成层：LLM 文本链、出图链、视觉评审链、确定性合成链
L2 领域层：故事对象流水线（脚本→圣经→资产→锁定→变体→摆位→场景→走查）
L1 地基层：真相源存储、schema 契约、配置环境、创作缓冲快照
```

**层归属铁律**：控制面仓承载 L4–L6，业务面仓承载 L1–L3 与 L7–L8；跨层调用只经声明的接口，禁止越层直连。

| SCN 场景合成 | L2/L7 | storyComposition、placements 端点族、编排器、sceneBackgroundReview、storySceneReview |

### 2.6 人工处理过程
- 审核批准/拒绝（非托管时）、低分候选特批、构图需求单确认、场景绑定人工确认——全部在审核界面内联完成并留痕。
- 托管模式下上述动作由守护台经同一审核通道自动批准（留审计）。

### 3.2 技术框架选型

## 4. 接口设计

### 4.1 用户接口
- 编辑器（创作者）：项目库→四工作室→锁定工作台→编排器→导出；一切 AI 产出以候选呈现，批准才落真相源。
- 守护台（操作者）：任务队列、会话时间线、审核卡片、资源状态、治理审计；生产动作一律经会话发起。

### 4.2 外部接口
| 接口 | 方向 | 说明 |
|---|---|---|
| 本地模型服务 /v1（chat/completions、responses、models） | 出 | 文本与视觉评审调用，全部经租约与 max_tokens 护栏 |
| 出图服务 API（prompt/queue/history/free） | 出 | 出图与显存释放，经租约 |
| 云端评审/翻译/配音（可选） | 出 | 必须有本地兜底路径，失败回退本地 |

### 4.3 内部接口（双平面间）
| 接口 | 说明 |
|---|---|
| `POST /api/control/resources/lease` / `release` | 资源租约申请/释放；kind 与客户端 scope 一一对应 |
| 事件分发 | 业务面 `events/registry.v1.json` + 控制面 eventDispatcher，正式链内确定性步骤使用 |
| 审核代理 | 业务面图片审核记录与批准经约定头与留痕字段互通（decidedBy 记录批准方） |
| 项目只读代理 | 控制面经业务面 API 读项目/台账/总账（禁止直接读文件系统） |

### 4.4 接口纪律
- 一切接口错误结构化（error code+message）；禁止静默失败与假成功。
- workspace 外路径拒绝；客户端按 scope 授权（clientAuth）；密钥文件不入库。

## 5. 运行设计

### 5.1 运行模块组合
- 生产态：业务后端+编辑器+控制面双端+本地模型服务+出图服务，五进程。
- 文档态：docsys 静态站点（可无服务直开）。
- 出图资源态：文本模型、视觉模型、出图服务经调度器换入换出，物理不共存。

### 5.2 运行控制
- 生命周期脚本（scripts/lifecycle/）：启动/停止/重启/状态；守护台生命周期在其仓脚本。
- 控制面的 start/stop/pause/resume/exit 为保护行为，任何自动化不得替代。

### 5.3 运行时间
单场景背景出图 ≤3 分钟；变体单件 ≤3 分钟；出图批次经 settle 窗口攒批避免模型反复装卸；台账轮询间隔 2–10s。

## 6. 系统数据结构设计

### 6.1 逻辑结构设计要点
- ProjectV1：项目主档（角色/资产/设置/_rev 乐观锁）。
- StoryV1：故事文档（节点/分支/选择/visuals.placements/backgroundAssetId）。
- PlanV1（story-assets/plan.json）：资产计划（assets[].references/lineart/poseVariants/stateVariants/stateRequirements/scenes[].composition）。
- StatesDoc（story-assets/states.json）：剧情状态表（scenes[].states[]：stateKey/label/evidence/relatedAssetIds）。
- 评审记录（reviews/*.jsonl）：三级审核与审图中心结论，追加式。
- 台账（/ai/tasks）：长任务进度与结果。

### 6.2 物理结构设计要点
纯文件真相源（JSON/JSONL/WebP/JPEG/PNG）；项目自包含目录可整体迁移；存储根可外置（STUDIO_STORAGE_ROOT）；创作缓冲 journal.jsonl + 快照轮转 20 份。

### 6.3 数据结构与程序的关系
合并语义集中在 saveStoryAssetPlan：记录数组按键并集、mergeRecordUpdates 允许声明键的入站更新；project.json 副本同步由写路径负责；编辑器与后端以 _rev 乐观锁防并发覆盖。

## 7. 系统出错处理设计

### 7.1 出错信息
全部结构化：error code（snake_case）+ 中文 message + 可选 detail；界面呈现面向用户文案，不出现研发术语。

### 7.2 补救措施
- 瞬断：断点续跑（限次）+ 看门狗自动恢复孤儿会话。
- 资源墙：显式失败+可重驱；自治线逐步自动化（卸载→验证→重试序列）。
- 评审通道不可用：挂起待审不盲批。
- 进程崩溃：持久化任务重启恢复；被中断任务标记 interrupted 且不得按成功计。

### 7.3 系统维护设计
治理审计全量落盘；retention 清理策略定期归档历史会话/日志；文档体系与代码同仓演进；配置变更留指纹与审批记录。
