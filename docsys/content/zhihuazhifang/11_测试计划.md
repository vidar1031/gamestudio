# 测试计划

> 范围：织话智坊全部测试活动的计划。执行结果按版本写入《测试分析报告》。
> 与《PRODUCTION_DEFECTS.md》四阶段基准、《运行时能力测试基准》配合使用，后两者为硬基准不可偏离。

## 1. 引言

### 1.1 编写目的
规定测试范围、策略、环境、用例组织、通过标准与职责，保证每一里程碑门口的验证可重复、可审计。

### 1.2 背景
系统含业务面（编辑器+后端+共享包）、控制面（守护台双端）、文档体系三类被测对象；生成类能力受本地模型波动影响，测试设计必须区分**确定性逻辑**（可无出图复跑）与**生成质量**（需出图与评审）两层。

### 1.3 定义
适应度函数：一条命令全跑的全部护栏。黄金基线：截图/指纹对照基线。四阶段基准：S0 启动硬检查→L1 硬门禁→L2 确定性事实源→L3 安全边界→后续生产验证。

### 1.4 参考资料
《软件需求说明书》需求编号（用例须回引编号）、《PRODUCTION_DEFECTS.md》、《运行时能力测试基准》。

## 2. 计划

### 2.1 软件说明
被测对象：故事生产链（脚本→…→导出）、治理链（审核/调度/看门狗/托管）、编辑器与守护台 UI、docsys 站点、（规划项）视频导出与自动演示。

### 2.2 测试内容总表

| 测试项 | 类别 | 覆盖需求编号 | 方式 |
|---|---|---|---|
| T1 静态护栏 | 单元/静态 | 全部 | typecheck+node --check+control 测试套件 |
| T2 四阶段生产基准 | 集成 | GOV/GEN 主干 | 现成脚本（control_production_test） |
| T3 确定性核心算法 | 单元 | GEN-01/03/04、VIS-04/05、SCN-03、3.4 合并语义 | 脚本/单测（无出图） |
| T4 生成质量门禁 | 集成 | VIS 全域、SCN-01/05、REV 全域 | 出图+评审实测（留台账证据） |
| T5 UI 探针 | 端到端 | 4.4 UI 规格、编辑器契约 | 无头浏览器探针（点击/拖放/落盘验证） |
| T6 黄金基线 | 回归 | 全局 | 截图/指纹对照 |
| T7 故障与恢复 | 韧性 | GOV-03、3.5 故障处理 | 杀进程/断连/中断重驱实测 |
| T8 文档体系 | 验收 | DOC-01/02 | 站点构建+链接+骨架完整性 |
| T9 视频与演示（规划项） | 集成 | RUN-02/03 | 样片三预设+演示全片播放 |

### 2.3 测试 1：静态护栏（T1）
- 输入：全仓源码。
- 输出：typecheck 零错误、node --check 全过、control 17 个测试文件全绿。
- 控制：每次提交前必跑（本地）；每波迭代门口径。
- 过程：npm run typecheck；node --check 各入口；node --test scripts/test/*.test.mjs（控制仓）。

### 2.4 测试 2：四阶段生产基准（T2）
- 输入：运行中四服务（模型/业务/控制/出图）。
- 输出：阶段检查全过；任一门不过即阻断后续阶段。
- 控制：严格分段执行，前一阶段未全过不得进入下一阶段（硬基准）。
- 过程：bash scripts/test/smoke_test_pipeline.sh；支持 --stage/--case/--stop-on-fail。

### 2.5 测试 3：确定性核心算法（T3）
- 输入：构造的计划/状态/故事样例（无出图）。
- 输出：拟合结构零 issue；缺口计算与预期一致；摆位命中预期变体；合并后既有记录更新不丢。
- 过程：node 脚本直调模块（storyStates.findStateGaps 等）断言；纳入 T1 套件滚动。

### 2.6 测试 4：生成质量门禁（T4）
- 输入：正式生产链（守护台会话）。
- 输出：三级审核留痕完整；无评审分不登记；坏变体（空手/多人/换装/跑题）不过验收门；评审不可用挂 pending。
- 控制：生成类验证必须走工具自身链路并在工具内留痕（禁止直接 API+原始输出判定充数）。

### 2.7 测试 5：UI 探针（T5）
- 过程：无头浏览器按真实用户路径操作（点选/拖入/保存/刷新回读），断言落盘与界面一致；选择器必须限定容器作用域（历史事故教训）。

### 2.8 测试 6：黄金基线（T6）
- 过程：基线库截图/指纹与当次产物对照；差异超阈值即评审：修复或经批准更新基线值。

### 2.9 测试 7：故障与恢复（T7）
- 过程：渲染中杀后端进程→重启→任务恢复且中断标记正确（不得按成功计）；控制面重启→孤儿会话自动恢复；调度器租约释放验证。

### 2.10 对培训的要求
测试执行人须先通读治理宪法三篇与四阶段基准；出图类测试须会读台账与评审记录。

### 2.11 进度安排与职责
| 时机 | 必跑项 | 责任人 |
|---|---|---|
| 每次提交前 | T1 | 开发者 |
| 每波迭代门 | T1+T3+T6 | 开发者+统筹师 |
| 里程碑门 | 全部（含 T2/T4/T5/T7） | 质量+负责人 |
| 发行前 | 全部+连续 3 故事零干预 | 负责人 |

## 3. 测试设计说明

### 3.1 用例组织
每个用例登记：标识（T#-序号）、回引需求编号、输入、预期输出、判定尺度、证据位置（台账/评审记录/截图）。

### 3.2 环境
固定四服务+本地模型+出图服务；端口见 SRS §4.3；测试项目目录独立（禁止污染正式项目）；调度器测试用隔离 state 文件（env 覆写）。

### 3.3 数据
确定性样例入测试夹具；生成类测试用真实小题材（3–5 场景）控成本；基线库入 testcases/ 目录管理。

## 4. 评价准则

### 4.1 范围
需求编号全覆盖为原则；未覆盖项必须在测试分析报告"未覆盖说明"中列明原因。

### 4.2 数据整理
证据统一三类：台账条目、评审/审计记录、截图/文件指纹；报告引用必须可回溯。

### 4.3 尺度
- 确定性逻辑：断言全过（零容忍）。
- 生成质量：评审分与人工复核双口径；坏变体漏过 0 容忍。
- 性能：出图单件 ≤3 分钟；画布 60fps；导出包 ≤5MB。
- 韧性：中断恢复后零数据损坏、零误判成功。
